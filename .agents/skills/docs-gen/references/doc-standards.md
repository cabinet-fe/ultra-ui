# docs-gen 文档标准

约束推送到 docs-server 的库文档。读者是 AI：它把文档当规格直接执行，写不清的地方会用开源库的训练知识脑补。每条规范都服务两个目标：**指令精确**、**示例足够**。服务端机制与理由见 [server-behavior.md](server-behavior.md)；各类文档骨架在 `templates/` 下按类型分文件，写满的范例见 [golden-sample.md](golden-sample.md)。

## Frontmatter（硬性）

每个 `.md` 从首字节起是 YAML frontmatter；`title` 必填非空白，否则整批推送失败。

| 字段 | 必填 | 权重 | 写法 |
| --- | :---: | :---: | --- |
| `title` | 是 | 10.0 | 「导出名 + 中文全称」：`Table 表格组件`、`useRequest 请求 Hook`；指南类带库名：`ui-core 安装与初始化` |
| `keywords` | 否 | 10.0 | 开发者会输入的检索词，8~20 个：公共属性 / 方法 / 错误类名（源码原样）、场景动宾短语（`分页`、`行内编辑`）、高频报错片段（`Token Expired`） |
| `aliases` | 否 | 10.0 | 别称，3~8 个：中英名、缩写、旧名、同类开源库里的叫法（`DataTable`、`Grid`） |
| `description` | 否 | 3.0 | 1~2 句：是什么 + 解决什么场景 + 关键能力枚举。它是 AI 在搜索结果里决定是否打开的依据 |
| 其他 | — | — | 忽略，不入索引 |

模板：

```markdown
---
title: Table 表格组件
description: 展示多行结构化数据的表格组件，支持客户端/服务端分页、列排序、行选择、虚拟滚动（10 万行）。
aliases: [DataTable, Grid, 数据表格]
keywords: [columns, dataSource, rowKey, onPageChange, 分页, 排序, 行选择, 虚拟滚动, 虚拟列表, 大数据量渲染]
---
```

格式要求（服务端严格 YAML，任一违反整批失败）：

- 文件首字节就是 `---`：无 BOM、无前导空行；两条分隔线独占一行、行尾无空格
- 值含 `: ` 或 ` #`，或以 `[` `{` `*` `&` `!` `|` `>` `%` `@` 或引号开头时，用双引号包裹
- 不写多行标量（`>-`、`|`）、不重复字段
- `keywords` / `aliases` 三种写法等价：YAML 列表、内联数组 `[a, b]`、逗号分隔字符串 `"a, b"`

keywords 写法（与服务端分词配合）：

- 中文用 2~6 字的原样短语，同义写法分别列出（`虚拟滚动`、`虚拟列表`），不写句子
- 标识符按源码原样（`rowKey`），不写 `row-key` / `row key` 变体，不重复 title 已有的词
- 不写疑问词与虚词（如何 / 怎么 / 使用 / 的）：查询端会把它们去掉

反模式：`title: 表格` + `description: 表格组件的使用方法`、无 keywords —— 搜 `DataTable`、`虚拟滚动`、`rowKey` 全部落空。

## 文件组织

文档放 `agent-docs/`，递归扫描全部 `.md`。`path`（相对路径，含 `.md`）是 AI 取文档的唯一键，也整串进检索索引（目录与文件名按 `-` `.` 等分隔符拆成可命中词元）：语义化、小写连字符、稳定，文件名要能表达主题；重命名等于让所有旧引用失效。

```text
agent-docs/
├── index.md              # 总览：定位、安装、模块 → 文档路径 速查表
├── guide/                # 指南：installation.md、configuration.md、quick-start.md
├── components/ 或 apis/  # API 参考：一个组件 / 类 / 高协同函数组 一篇
├── recipes/              # 场景方案：一个端到端场景一篇
└── troubleshooting/      # 排障：common-errors.md；迁移：migration-v2.md
```

- 单篇 100~500 行，一主题一篇，按「开发者意图」而非源码文件划分。低于 100 行时检查是否示例缺失或粒度过碎（`index.md` 除外）；超过 500 行拆成 API 参考 + 场景方案
- 微小函数按逻辑模块合并（`type-guards.md`），不为 2 行函数单建文件；全库 API 不塞一篇

## 文档类型与章节词表

六类文档，各有固定的 `## ` 章节集。章节名是受控词表，AI 会按这些名字直接请求切片。新建文档时只读对应类型的一份骨架：

| 类型 | 适用 | `## ` 章节（按序） | 骨架 |
| --- | --- | --- | --- |
| 总览 | `index.md`，每库一篇 | `安装` `模块速查` | `templates/overview.md` |
| API 参考 | 组件、类、Hook、函数组 | `快速上手` `API 签名` `参数说明` `方法与事件`（可选） `典型示例` `注意事项` `常见问题`（可选） | `templates/api-reference.md` |
| 指南 | 安装、配置、快速开始、概念 | `前置条件` `步骤` `完整示例` `验证` `注意事项` | `templates/guide.md` |
| 场景方案 | 端到端业务场景 | `场景` `完整示例` `要点说明` `注意事项` | `templates/recipe.md` |
| 排障 | 运行时 / 构建期报错 | 每个问题一节，标题为报错原文（含错误码）或症状短语 | `templates/troubleshooting.md` |
| 迁移 | 大版本破坏性变更 | `破坏性变更` `迁移步骤` `新旧对照` | `templates/migration.md` |

「可选」章节无内容时省略，不留空章节。

章节规则：

- 主要分段只用 `## `，名称与上表完全一致（不加编号、emoji、锚点、尾随说明）；`###` 用于章节内小节
- **每个 `## ` 章节自包含**：AI 可能只取回这一段。import、前置初始化、示例内引用的变量与类型都写在本章节内；禁止「同上」「见快速上手」「import 略」
- 正文 H1 后第一段是概述：一句话说明从哪个包导出什么、做什么；它常被当作搜索片段展示

## 写作规则（指令精确）

- 事实用确定句：「`rowKey` 默认 `'id'`」。禁用模糊词：通常、一般、可能、大概、建议、尽量、等等、若干、适当、合理。有条件差异就写条件句：「`virtual: true` 时 `height` 必填」
- 约束用 必须 / 禁止 / 仅 / 至少 / 最多 + 精确值：「`pageSize` 取值 10~200，默认 20」
- 每个参数五要素齐全：名称、类型、默认值、必填、取值范围或约束（枚举列全，互斥与依赖关系写明）。类型块的 JSDoc 与 `## 参数说明` 表都要覆盖默认值
- 每个方法：签名、返回类型、同步 / 异步、抛出的错误类型与触发条件
- 类型定义优先于文字：API 用紧凑类型块 + JSDoc 表达；表格只补默认值 / 必填 / 约束
- 报错原文照抄（含错误码），不改写——开发者会拿原文检索；高频报错片段进 keywords
- 与开源同类库或旧版本不同的命名 / 行为，在 `## 注意事项` 用 `> [!WARNING]` 逐条写「本库是 X，不是 Y」
- 二选一写决策规则：「需要 A 时用 X；需要 B 时用 Y」，不罗列两者让 AI 自己判断
- 版本相关行为标具体版本：`v2.0 起`、`v1.x 已废弃`
- 只文档化公共导出；排除 `@internal`、`@private`、未导出符号
- 不写：营销语（强大、优雅、开箱即用）、背景故事、团队信息、内部实现（除非影响用法）、规划与待办、密钥、内网拓扑
- 中文撰写；标识符、路径、命令、取值用反引号并保留英文；代码块标语言（`ts`、`go`、`bash`）

## 示例规则（示例足够）

每个代码示例都必须**自包含可运行**，同时满足：

1. `import` / `require` / `use` 写全，用真实公共包路径（`@company/ui-core`）；禁止 `../../src` 相对路径
2. 运行前提写全：初始化、注册、Provider 包裹、配置对象、环境变量——不写就跑不起来的都写
3. 示例内引用的变量、类型、数据在示例内定义；需替换的值用 `<占位符>` 标出
4. 展示结果处理：返回值怎么用；有错误路径的 API 必须展示错误捕获
5. 关键行注释「为什么」；期望输出用 `// => ` 标出
6. 不含无关内容：无业务布局、样式、埋点、与主题无关的分支

禁止的片段写法：`// ...`、`// 省略`、`// 同上`、`// 参见 xx`、`import { X } from '...'`、使用未定义的变量。

各章节的示例要求：

| 章节 | 要求 |
| --- | --- |
| `## 快速上手` | 1 个，最少代码，含必要前置步骤（初始化、Provider） |
| `## 典型示例` | 2~3 个，各覆盖一个核心场景，每个自包含（import 重复写）；`## 参数说明` 里的复杂参数（回调签名、配置对象）至少在一个示例中出现 |
| `## 完整示例`（指南、场景方案） | 1 个端到端实现：全部文件、全部 import、初始化、调用、结果与错误处理；多文件时每个文件一个代码块，首行注释文件路径（`// src/http.ts`） |
| `## 常见问题` / 排障各节 | 每个问题给修复代码，不只给文字 |

## 自检清单

推送前逐篇核对：

- [ ] frontmatter：首字节 `---`；`title` = 导出名 + 中文全称；`description` 讲清是什么 + 解决什么；`keywords` 8~20 个含标识符与场景词；`aliases` 含中英别称
- [ ] 章节名与文档类型的词表完全一致；每个 `## ` 章节自包含
- [ ] 每个参数五要素齐全；每个方法有签名、返回、错误
- [ ] 每个示例自包含可运行，无 `// ...`；`## 快速上手` 1 个、`## 典型示例` 2~3 个、指南 / 场景方案有 `## 完整示例`
- [ ] `## 注意事项` 列出与开源库 / 旧版的差异与禁止用法
- [ ] 全文无模糊词、无营销语、无内部实现与敏感信息
- [ ] 单篇 100~500 行；`path` 语义化稳定
