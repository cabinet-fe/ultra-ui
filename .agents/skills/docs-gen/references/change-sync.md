# 变更同步：库代码改动 → 文档影响判定

库代码改动后，按本文确定改动范围、判定哪些文档的哪些章节要改、改完输出报告。只改受影响的章节，改完的篇目过 [doc-standards.md](doc-standards.md)「自检清单」。`agent-docs/` 不存在时不走本文，走 SKILL.md「3. 构建文档」。

## 确定改动范围

按顺序取第一个成立的情形：

| 情形 | 范围 |
| --- | --- |
| 用户指定 commit / tag / 分支 / PR | `git diff <base>..<head>` |
| 本次会话刚改完库代码 | 会话中改动的文件；用 `git diff HEAD` 复核实际 diff |
| 用户只说「同步文档」，工作区有改动 | `git status --short` + `git diff HEAD` |
| 工作区干净 | 自 `agent-docs/` 最后一次提交以来的源码改动：`git diff $(git log -1 --format=%H -- agent-docs/)..HEAD` |

- `agent-docs/` 没有提交记录（文档刚建）：范围只取工作区未提交的源码改动
- 无 git 且非本会话改动：向用户询问改了什么，禁止猜
- **读 diff 正文，不只看文件名**：文件名分不出改的是公共签名还是私有实现

## 判定是否影响文档

只有**公共导出可达**的改动才影响文档。公共导出的判定：从包入口可达（`package.json` 的 `exports` / `main` / `types` 指向的文件、Go 非 `internal/` 包的大写标识符、Python `__all__`），且未标注 `@internal` / `@private`。未导出符号改多少都不影响。

| 改动 | 影响 | 要改的文档 → 章节 |
| --- | :---: | --- |
| 新增公共导出（组件 / 类 / 函数 / 类型 / 常量） | 是 | `index.md` `## 模块速查` 加行；按 doc-standards.md「文件组织」并入现有篇目或新建篇目（读对应 `templates/`）；导出名进 keywords |
| 删除 / 重命名公共导出 | 是 | 删篇或改 title，旧名进 aliases；`index.md` 速查改行；破坏性变更写进 `troubleshooting/migration-v<N>.md` 的 `## 破坏性变更` `## 新旧对照` |
| 参数 / 属性：增删、类型、默认值、必填、取值范围、互斥依赖 | 是 | `## API 签名`（类型块与 JSDoc）、`## 参数说明`；用到该参数的 `## 快速上手` `## 典型示例`，以及其他篇目的 `## 完整示例`；参数名进出 keywords |
| 方法 / 回调 / Hook 返回值：签名、返回类型、同步异步、抛错类型与触发条件 | 是 | `## 方法与事件`；示例中的返回值处理与错误捕获 |
| 报错文案、错误码、错误类名 | 是 | `## 常见问题` 与排障篇的小节标题（报错原文照抄）及修复代码；keywords 中的报错片段 |
| 可观察行为变了但签名没变（默认行为、边界处理、副作用、性能约束） | 是 | `## 注意事项` 加条并标版本（`v<X> 起`）；示例的 `// =>` 期望输出 |
| 加 `@deprecated` | 是 | `## 注意事项` `> [!WARNING]`：「`<旧 API>` 自 v<X> 废弃，改用 `<新 API>`」；示例改用新 API |
| 包名、安装命令、peer 依赖、运行时最低版本、初始化 / Provider / 配置项 | 是 | `index.md` `## 安装`；`guide/` 对应篇 `## 前置条件` `## 步骤` `## 完整示例` |
| 版本号（`package.json` `version`、Go module 发布 tag 等） | 是 | `index.md` 概述段的版本；主版本升且含破坏性变更 → 新建迁移文档 |
| README / CHANGELOG | 视内容 | 记录了上面任一改动 → 按对应行处理，事实以源码为准核对；只是措辞、徽章、贡献说明 → 否 |
| 内部实现、重构、性能优化，公共签名与可观察行为不变 | 否 | — |
| 测试、CI、lint、格式化、构建配置、依赖升级（不改公共 API） | 否 | — |
| 注释、日志文案、私有类型、`internal/` 目录 | 否 | — |

分不清「可观察行为是否变」时读同一改动的测试 diff：断言变了就是行为变了。没有测试改动就向用户确认，禁止按猜测写「可能」，也禁止默认「不影响」。

## 定位受影响的篇目

- 路由表：`agent-docs/index.md` `## 模块速查`，导出名 → 文档路径
- 引用检索：`rg -l -F '<标识符>' agent-docs/`，title、keywords、示例代码都会命中；`recipes/`、`guide/` 的 `## 完整示例` 常引用该导出，命中的篇目全部纳入，不只改主篇
- 改报错文案时用旧文案原文检索
- 速查表没有该导出且检索无命中 → 现有文档遗漏，按「新增公共导出」处理

## 更新

- 只改受影响章节；同一参数在多篇示例中出现要全部改，不留旧签名
- 改后每个 `## ` 章节仍自包含、示例仍可运行；同一示例内不并存新旧写法，版本差异只写在 `## 注意事项`
- 删导出：删对应篇目或小节，不留「已移除」空节；`index.md` 速查同步删行
- 增删篇目后 `index.md` `## 模块速查` 的路径与实际文件一致
- 改完的每篇过 doc-standards.md「自检清单」
- 完成后进入 SKILL.md「4. 执行推送」

## 同步报告

向用户输出，格式固定：

```text
变更同步报告（范围：<base>..<head> | 工作区 | 本会话）

| 改动 | 判定 | 文档 → 章节 | 处理 |
| --- | --- | --- | --- |
| `Table` 新增 `sticky` 属性，默认 `false` | 影响 | `components/table.md` → API 签名、参数说明、典型示例 | 已更新 |
| 报错 `Invalid token` 改为 `Token Invalid` | 影响 | `troubleshooting/common-errors.md` → 小节标题；`apis/request.md` → keywords | 已更新 |
| `useTableSort` 内部缓存重构 | 不影响 | — | 未导出 |
| `request` 超时后是否重试 | 待确认 | `apis/request.md` → 注意事项 | 已向用户提问 |
```

- 无一条影响也要输出报告并写明理由，不能静默结束
- 判定不了的改动列为「待确认」并向用户提问，不擅自定性
